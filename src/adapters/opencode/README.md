# OpenCode adapter

Official plugin docs: https://opencode.ai/docs/plugins/ (checked 2026-10-20, against OpenCode 1.19.3). Event
shapes: `packages/sdk/js/src/v2/gen/types.gen.ts` at tag `v1.19.3` in https://github.com/anomalyco/opencode.

## How it hooks in

OpenCode has no shell hooks. Its extension point is a JS/TS **plugin** that it loads from
`{plugin,plugins}/*.{js,ts}` in its config folder and runs inside its own (Bun) process. The plugin then receives
every bus event.

`agentwatch install --tool opencode` writes **its own file**, `~/.config/opencode/plugins/agentwatch.js`
(`$XDG_CONFIG_HOME/opencode/...` when that is set; OpenCode uses the same folder on Windows). No file belonging to
the user is edited, so no backup is needed, and `uninstall` deletes the file. The file starts with a marker line:
install refuses to overwrite a file at that path without it, and uninstall leaves such a file alone. OpenCode loads
plugins only at startup, so it has to be restarted after installing.

The plugin (generated by `plugin.ts`) passes the events below to `agentwatch hook --tool opencode`, one detached
background process per event, with the payload as the last argument and no shell. Like the other tools' hooks, it
never blocks or throws into OpenCode. It sends only the fields `normalize.ts` reads, with text cut to 500 characters,
because raw events carry file diffs, shell commands and question text.

Why an argument, not stdin: `opencode run` exits right after its final `session.idle`. Measured under OpenCode's own
Bun (1.3.14, Windows), an attached child, or one fed through a stdin pipe, dies with OpenCode and that last event is
lost. A detached child with a stdin pipe never runs at all. Detached, with the payload as an argument, every event
arrived. It sends a
`session.status` only when it changes, because OpenCode repeats `busy` several times per turn. The payload is
wrapped in an envelope: `{ event, directory, pid, at, title?, rootSessionID?, afterError? }`.

| OpenCode event | Status | Notes |
|---|---|---|
| `session.status` `busy` | `working` | |
| `session.status` `retry` | `working` | Message: `Retrying: <reason>`. |
| `session.status` `idle` | — | Not sent; `session.idle` says the same. |
| `session.idle` | `done` | After an error: ignored, so the error stays. After Esc (`MessageAbortedError`): `idle`, "Interrupted". |
| `session.error` | `error` | Message from `error.data.message`. `MessageAbortedError` (Esc) is ignored. |
| `session.deleted` | `ended` | |
| `permission.asked` | `needs_input` | Message: `Permission needed: <edit\|bash\|...>`. |
| `permission.updated` | `needs_input` | The older name in the v1 SDK types; 1.19.3 sends `permission.asked`. |
| `permission.replied` | `working` | On `reject`, `session.idle` follows within milliseconds. |
| `question.asked` | `needs_input` | Message: "Has a question for you" (the question text is not sent). |
| `question.replied`, `question.rejected` | `working` | |
| `session.created`, `session.updated` | — | Only remembered by the plugin: directory, title, `parentID`. |

- **Session id and folder:** OpenCode's `sessionID` and the session's `directory`.
- **Title:** OpenCode names each session itself (e.g. `Adding "world" to hello.txt`) and the plugin attaches the
  latest name to the next status event, sent with `titleSource: "tool"`. The placeholder
  `New session - <ISO time>` is ignored. A rename while idle shows with the next activity.
- **Subagents** run in child sessions (`parentID`). Their own busy/idle is ignored, because the parent is busy
  throughout. Their permission prompts and questions are shown on the top-level session (`rootSessionID`).
- **Host:** from the environment OpenCode passes on, e.g. `WT_SESSION` → "Windows Terminal".
- **pid:** the OpenCode process (`process.pid`, which equals `OPENCODE_PID`). OpenCode sends no event when you quit,
  so the server drops the session once that process is gone (within a minute).
- **Order:** `at` is when the plugin saw the event. Hooks are separate processes and can arrive out of order, so
  the server uses this time to drop late, stale ones.
- **`opencode run`:** the session shows its final status until the server's next health check (at most a minute)
  sees that the process has gone, then disappears.

## Fixtures

Real captured payloads (OpenCode 1.19.3 TUI in Windows Terminal, OpenAI via a ChatGPT login, 2026-10-20), with paths
replaced: `session-created`, `session-updated-title`, `session-status-busy`, `session-status-idle`, `session-idle`,
`permission-asked-edit`, `permission-asked-bash`, `permission-replied-once`, `permission-replied-reject`,
`question-asked`, `question-replied`.

Constructed from the SDK types (these didn't fire in the capture): `session-status-retry`, `session-error`,
`session-error-aborted`, `session-deleted`, `session-created-child`, `question-rejected`, `permission-updated`.

## Known gaps

- **Not verified by capture:** errors, retries, Esc, subagent sessions, deleting a session, and the OpenCode desktop
  app and IDE extensions. The mappings above follow the SDK types for these.
- **No end event on quit:** a quit session is removed only when the server notices the OpenCode process has exited.
  Older sessions from the same process (after `/new`) stay until they expire.
- **Plugin API in flux:** OpenCode's `dev` branch is moving to a new plugin API (`@opencode/plugin`, `Plugin.define`).
  This adapter targets the API 1.19.3 ships; a later release may need an update.
- As with Claude Code's `CLAUDE_PID`, the pid also enables the approval watcher. OpenCode already reports approvals
  (`permission.replied`), so the watcher only matters if that event is late.
